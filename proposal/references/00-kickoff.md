# 0. 착수 — 사업 설정 파일과 역산 일정표

## 할 일

1. 현재 폴더와 **하위 폴더**에서 RFP 관련 파일을 찾는다(PDF, XLSX, DOCX, HWP, PPTX. 예: `1. RFP 원본\`). 목록을 사용자에게 보여 주고 빠진 파일이 없는지 묻는다.
   - 이미 만든 분석·질의 산출물(예: `2. 분석\`, `3. 질의\`, `4. 담당 배분\`)이 있으면 새로 만들지 않고 입력으로 쓴다. `project.md` "자료 경로"에 적는다.
   - HWP는 직접 읽을 수 없다. PDF로 변환해 달라고 요청한다.
2. `제안작업/` 폴더를 만들고 `assets/project-template.md`를 `제안작업/project.md`로 복사한다.
3. RFP에서 알 수 있는 항목(사업명, 발주처, 기간, 계약 방식, 평가 비율, 설명회일, 필수 목차)은 채운다. 모르는 항목만 사용자에게 묻는다. 한 번에 묻고, 모르면 비워 두고 진행해도 된다고 알린다.
   - 꼭 필요한 것: **제출일**(역산 일정의 기준), **PPT 템플릿 유무**, **분담 여부(장별 담당자)**
4. **템플릿·공통 자료 확인**
   - 사업 폴더에 `디자인.md`가 있으면 경로를 `project.md`에 적는다. 없고 템플릿이 있으면 PPT 단계 전에 만들자고 제안한다(템플릿 실측 + 회사 가이드 병합).
   - 사업 폴더에서 PPT 템플릿을 찾는다(`*탬플릿*`, `*템플릿*`, `*template*` 폴더나 파일). 찾으면 `project.md` "자료 경로"에 적는다.
   - 공통 폴더(`C:\workFISH\제안공통\`)의 구성을 확인하고 경로를 `project.md`에 적는다.
   - 회사 자산 요청 목록을 보여 준다(`references/company-assets.md`). 지금 없는 것은 나중에 받아도 된다.
5. 역산 일정표를 만든다(아래).
6. 사용자에게 다음 단계(분석)를 제안한다.

## 역산 일정표

제출일에서 거꾸로 단계별 마감일을 잡는다. 제출일이 미정이면 "D-일" 상대 일정으로 만든다.

기본 배분(제출까지 영업일 N일 기준, 비율은 사업 규모에 맞게 조정):

| 단계 | 비율 | 비고 |
|---|---|---|
| 분석 (관문 A) | 15% | 설명회 전이면 설명회 질의를 먼저 뽑는다 |
| 질의 | 설명회·질의 마감에 맞춤 | 질의 마감일이 우선 |
| 전략·목차 (관문 B) | 10% | |
| 원고 (관문 C) | 35% | **배점 큰 장부터** 작성 |
| PPT | 25% | 배점 큰 장부터 제작, 디자인 보정 포함 |
| 검수 (관문 D) | 10% | 최소 2일. 제출 전날은 비워 둔다 |
| 예비 | 5% | 인쇄·전자입찰·서류 날인 |

규칙:
- **배점 큰 장과 리스크 큰 장을 앞에 배치한다.** 마감 직전에 뒤쪽 장이 대충 채워지는 문제를 막기 위해서다. 배점이 공개되지 않았으면 RFP에서 강조한 영역(평가 비율, 필수 기재 항목, "필수" 표시)으로 추정하고 [가정]으로 표시한다.
- 주말·공휴일은 영업일에서 뺀다. 발표 준비(PM 리허설) 일정도 넣는다.
- 결과는 `00_일정/역산일정.md`에 표로 쓰고 `project.md`의 주요 일정에도 반영한다.

## 결과 보고 예

"제안작업 폴더와 사업 설정 파일을 만들었습니다. 제출일 10월 10일 기준 역산 일정은 분석 9/25, 전략 9/29, 원고 10/6, PPT 10/8, 검수 10/9입니다. 템플릿과 이전 수주 제안서는 나중에 주셔도 됩니다. 분석을 시작할까요?"
