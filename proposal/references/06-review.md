## 사람이 판단할 검수

자동 검수 결과를 바탕으로 다음을 직접 확인한다.
- **바꿔치기 테스트**: 헤드메시지를 무작위로 10개 골라, 발주처 이름만 바꿔 다른 사업에 넣어도 말이 되는지 본다. 말이 되면 다시 쓴다.
- **Win theme 반복**: 각 Win theme이 최소 세 장 이상에서 증명되는지.
- **수치 일관성**: 자동 대조에서 표시된 값이 정말 다른 것인지(단계별로 다를 수 있다) 확인.
- **발주처 용어**: 시스템 이름·요구 명칭이 RFP 표기와 같은지.
- **필수 제출물**: 분석보고서 12장의 제출 체크리스트(확약서, 인력 요약표, WBS 엑셀, 과제별 공수 등).
- **PPT**: 렌더링 이미지로 경고 신호(`visual-patterns.md` 3장)를 다시 훑는다.

## 검수 항목으로 올리는 기준

- **원문 맥락을 확인한 뒤에만 올린다.** 글자 대조로 찾은 후보는 ① 요구사항 엑셀의 상세 셀 전체(기능 설명 안에 근거가 숨어 있을 수 있다) ② RFP 이미지 페이지(일정표·구성도·I/F 목록) ③ 해당 장표의 제목·주변 글을 확인한다. 단위 차이(요건 3건 vs 서비스 4개)나 요약·중첩 표현은 오류로 보지 않는다. 항목마다 근거 위치를 적고, 근거를 못 찾으면 올리지 않는다.
- **실제 오류·불일치만 올린다.** 숫자·범위·일정·RFP 불일치처럼 내용이 틀린 것만 넣는다. 도구명 통일, 라벨 문구 다듬기, 설명 한 줄 추가 같은 말바꾸기는 넣지 않는다. 판단 기준: "안 고치면 틀린 내용이 남는가?"
- **찾은 것은 보고하고, 고치는 것은 사용자가 고른 항목만.** 보고 목록 전체에 "만들어줘·반영해줘"라고 해도 전건 승인으로 보지 않는다. 애매하면 어느 항목인지 묻는다.
