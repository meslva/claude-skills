# `/제안서` 스킬 사용법

> RFP를 받아 분석부터 제안서 PPT·검수까지 함께 진행하는 Claude 스킬이다.
> 설치 위치: `C:\Users\NB-124\.claude\skills\proposal\` (한글 명령 연결: `...\skills\제안서\`)

---

## 1. 한눈에 보기

- **부르는 법**: 입력창에 `/제안서` 또는 `/proposal`. 명령으로 부를 때만 동작하고, 평소 대화에는 끼어들지 않는다.
- **한 번에 끝나지 않는다.** 네 번의 관문(분석·전략·원고·최종)에서 멈추고 확인을 받는다. 며칠에 걸쳐 여러 번 불러 쓴다.
- **어디까지 했는지 기억한다.** 진행 상태는 작업 폴더의 `제안작업/project.md`에 저장된다. 다음 날 `/제안서`만 입력하면 이어서 진행한다.

## 2. 설치와 준비

**다른 PC에 설치**: `제안서스킬_설치파일.zip`을 풀어 `proposal`, `제안서` 두 폴더를 `C:\Users\<사용자>\.claude\skills\` 아래에 둔다. 설치 후 **새 세션**을 열어야 명령어가 보인다. `/제안서`가 목록에 없으면 `/proposal`을 쓴다(동작은 같다). PPT 렌더링 확인에는 PowerPoint, 스크립트 실행에는 Python(python-pptx, openpyxl, pdfplumber, pypdfium2)이 필요하다.

1. 사업별 폴더를 하나 만들고 RFP 파일을 넣는다(PDF, 요구사항 엑셀, Word 등).
   - HWP는 읽지 못한다. PDF로 변환해서 넣는다.
2. Claude 앱에서 그 폴더를 작업 폴더로 연다.
3. (있으면) 회사 PPT 템플릿, 이전 수주 제안서, 회사 소개·실적·인력 자료를 준비한다. 없어도 시작할 수 있다.

## 3. 명령어

| 입력 | 하는 일 | 끝나면 |
|---|---|---|
| `/제안서` | 처음이면 착수, 아니면 진행 상태를 보고 다음 할 일을 제안 | |
| `/제안서 착수` | 사업 설정 파일 생성, 제출일 기준 역산 일정표 | 제출일 등 모르는 정보를 묻는다 |
| `/제안서 분석` | 분석보고서, 요구사항 매트릭스(엑셀), 용어사전 | **관문 A**: 분석 결과 확인 |
| `/제안서 질의` | 질의서 엑셀(발송용·설명회·내부관리) | 발송은 사람이 직접 |
| `/제안서 전략` | Win theme, 차별화, 가정, 목차·배점 배분, 추적 대상 | **관문 B**: 전략·목차 승인 |
| `/제안서 원고` | 전 장 장표별 원고(배점 큰 장부터) | **관문 C**: 원고 승인 |
| `/제안서 원고 2장` | 2장 원고만 작성·수정 | |
| `/제안서 ppt` | 확정 원고로 PPT 제작 → PowerPoint로 렌더링해 확인·보정 | |
| `/제안서 ppt 2장` | 2장만 다시 제작 | |
| `/제안서 ppt 밀도=4` | 밀도(내용의 양)를 정해 제작. 1~5, 기본 3. 높이면 내용을 더해 빈 공간을 채우고, 낮추면 중요하지 않은 내용을 뺀다. 글자는 기본 크기로 시작하고, 원본 내용이 넘칠 때만 줄인다(하한 8pt). 추가한 내용은 별도 블록으로 넣고, 구역끼리 밀도가 고르게 맞춘다. `ppt 2장 밀도=5`처럼 함께 쓴다 | 예전 상/중/하 = 4/3/2 |
| `/제안서 테마 <템플릿> <PPT>` | 이미 만든 PPT에 템플릿(PPTX·PDF)의 스타일(색·글꼴)을 입혀 새 파일로 저장. 구조·틀·배치는 그대로 | 바꿀 색·글꼴 대응표(asis/tobe) 확인 후 적용 |
| `/제안서 테마 <템플릿>` | 앞으로 만들 PPT가 템플릿 색·글꼴을 따르도록 브랜드 설정을 만든다 | 브랜드 값 확인 |
| `/제안서 검수` | 누락(추적표), 모호 표현, 수치 불일치, 완성도 점검표 | **관문 D**: 최종 승인 |
| `/제안서 일정` | 역산 일정 다시 계산 | |
| `/제안서 상태` | 진행 상황 보고 | |

명령어 뒤에 자연어를 붙여도 된다. 예) `/제안서 원고 3장 플랫폼 경매 부분 더 구체적으로`
관문에서는 평소 대화처럼 고칠 점을 말하면 된다. 예) "Win theme 2번 빼고 보안 쪽으로 바꿔 줘", "승인".

## 6. 여러 사람이 함께 쓸 때

- **PM이 전체 초안을 만들고, 장별 담당자가 자기 장을 고치는** 방식이다.
- 모두 **같은 작업 폴더**를 써야 한다(공유 드라이브·Git 등). `project.md`에 전략·용어·담당이 있어서, 누가 `/제안서 원고 3장`을 불러도 같은 톤으로 쓴다.
- 원고 파일은 장별로 나뉘어 있다. 담당자는 자기 장 파일만 고친다.
- 원고 형식(`### [장-절-번호] 제목`, `- 헤드메시지:` 같은 줄)은 바꾸지 않는다. 검수 스크립트가 이 형식을 읽는다.
- 다 고친 뒤 `/제안서 검수`를 돌리면 장마다 달라진 수치·용어, 누락을 찾아 준다.

## 7. 원고의 표시 읽는 법

| 표시 | 뜻 | 할 일 |
|---|---|---|
| `[근거 필요]` | 수치·주장의 출처가 없다 | 출처를 넣거나 문장을 뺀다 |
| `[자산 필요: 무엇]` | 회사 자료가 필요하다 | 해당 자료를 준다 |
| `[가정: 내용]` | 확인 전 전제로 썼다 | 질의 답변 후 확정하거나 가정 페이지에 둔다 |

스킬은 회사 실적·인력 경력·효과 수치를 **지어내지 않는다.** 위 표시가 남은 칸은 사람이 채워야 한다.

## 8. PPT 품질을 올리는 법

- **회사 공통 폴더** `C:\workFISH\제안공통\`의 공통 가이드와 수주 제안서를 분석해 스킬에 반영해 두었다(`references/company-guide.md`, `visual-patterns.md` 6장). 글꼴·크기·색·표 서식·번호 체계·필수 삽입물(로고, 고지 문구, 예시 도장)을 이 규칙대로 만든다.
- **사업 템플릿을 주면**(사업 폴더에 둔다. 예: `글로비즈\0. 탬플릿\`) 템플릿의 표지·목차·간지·본문 장표를 원형으로 복제해 글자만 바꾸므로 틀이 템플릿과 똑같이 나온다. 템플릿이 없으면 회사 가이드 서식의 기본 디자인으로 만든다.
- 본문 장표는 수주 제안서처럼 **헤드메시지 → 슬로건·영문 키워드 → 주 도식 + 보조 블록 → 하단 요약 바**로 채운다. 기둥 매트릭스, 허브 4사분면, 화면 콜아웃, 순환 링, 등급 피라미드, 스텝 레일, 탭 패널, KPI 띠 등과 회사 아이콘 345개를 쓴다. 결과 예시: `글로비즈\9. 제안서스킬\예시PPT\제안서스킬_예시PPT_v2.pptx`.
- **이전 수주 제안서나 좋은 장표 샘플을 주면** 스킬이 장표 유형·배치·도식을 분석해 패턴 라이브러리에 추가한다. 품질에 가장 큰 영향을 준다.
- 표·차트·간트·아키텍처는 **PPT에서 바로 고칠 수 있는 도형**으로 만든다. 글자를 고치려고 다시 그릴 필요가 없다.
- 만든 뒤 PowerPoint로 장표를 이미지로 뽑아 겹침·넘침·빈 공간을 스스로 확인하고 고친다(PowerPoint가 설치된 PC 필요).

## 9. 알아 둘 한계

- 분석 한 단계에도 시간이 걸린다. 몇 분 만에 완성본이 나오지 않는다.
- 화면 콜아웃의 화면은 캡처가 없으면 도형 목업(예시 도장 포함)으로 들어간다. 실제 화면 캡처를 주면 그것으로 바꾼다.
- HWP 파일, 스캔 이미지로만 된 PDF는 내용 파악에 한계가 있다(이미지로 읽을 수는 있다).
- 가격(견적)은 산정하지 않는다. 규모 추정은 초벌이며 가격 산정용이 아니다.
